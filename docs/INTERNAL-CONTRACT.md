# CUSA SSO — Implementation contract

Backend Node.js22.12+, ESM TypeScript, Express5, React and MariaDB10.11+ follow MVC. Models own SQL/transactions, controllers handle HTTP, routes register middleware, services provide integrations, and React pages are the View. API JSON errors `{error: string, code?: string}`. All dates ISO serialized. All IDs UUID strings. Frontend same origin via Vite proxy `/api` -> localhost:4000. Production Express serves web/dist behind HTTPS. Deployment-specific credentials, remote MariaDB/TLS, Google/Gmail and throughput still require target-environment validation; no compliance certification is implied.

Database exports from db.ts: `query<T>(sql: string, params?: any[], connection?: PoolConnection): Promise<T[]>`, `execute(sql, params?, connection?): Promise<ResultSetHeader>`, `transaction<T>(fn: (connection: PoolConnection)=>Promise<T>):Promise<T>`, `pool`. Config from config.ts named `config` has dbHost,dbPort,dbName,dbUser,dbPassword,dbTls,dbCaFile,port,appOrigin,nodeEnv,sessionSecret,encryptionKey,googleClientId,googleClientSecret,mailMode,gmailSender,gmailRefreshToken,googleServiceAccountEmail,googleServiceAccountPrivateKey,sessionHours,otpMinutes,configured,trustProxy.

USER REQUIRES MVC. Root owns `config.ts`, `middleware/security.ts`, `services/crypto.ts`, `services/mail.ts`, `controllers/authController.ts`, `models/authModel.ts`, `routes/authRoutes.ts`, `app.ts`, `index.ts`. All SQL belongs in models, HTTP handling in controllers, path registration in routes. Security middleware exports `requireAuth` (full session), `requireAdmin`, `csrfProtection`, `attachIdentity`, `rateLimit(bucket,limit,windowSeconds)`, `audit(req,event,target?,metadata?,connection?)`, `HttpError(status,message,code?)`. `services/crypto.ts` exports `randomToken(bytes=32)`, `hashToken(value)`, `seal(value)`, `unseal(value)`, `safeEqual(a,b)`. All API writes require Origin + X-CSRF-Token except SSO token and introspect (API-key authentication). Auth middleware sets req.identity as types.ts. Root implements current-session setup, TOTP/email OTP and Google auth. Admin router named `adminRouter` mounted `/api/admin`. SSO router named `ssoRouter` mounted `/api/sso`.

Schema owners coordinate fields. Tables: allowed_emails(id,email,role,created_at), users(id,google_sub,email,name,avatar,totp_secret,totp_last_step,created_at,last_login_at), sessions(id,token_hash,user_id,kind,csrf_token,mfa_method,authenticated_at,created_at,expires_at), oauth_flows(state_hash,browser_hash,nonce,verifier,return_to,expires_at), otp_challenges(id,session_id,code_hash,attempts,created_at,expires_at,consumed_at), mfa_enrollments(session_id,secret,expires_at), rate_limits(bucket_hash,hits,reset_at), audit_logs(id,actor_id,actor_email,event,target,ip,metadata,created_at), applications(id,name,description,redirect_uri,created_at,revoked_at), api_keys(id,application_id,name,prefix,key_hash,scopes,created_at,expires_at,last_used_at,revoked_at), authorization_codes(code_hash,application_id,user_id,session_id,redirect_uri,code_challenge,expires_at,consumed_at), access_tokens(token_hash,application_id,user_id,session_id,scope,created_at,expires_at,revoked_at). MariaDB datetimes UTC; JSON parsed consistently. No implicit DB initialization or production writes on server startup.

Frontend API contract:

- GET /api/auth/google/start?returnTo=... redirects; callback -> /login?auth=success or /login?auth=error. After Google login pending session must complete email OTP (default) or TOTP. POST /api/auth/otp/send {}, /api/auth/otp/verify {code,reference}, /api/auth/totp/verify {code}; verify returns {ok:true}. POST /api/auth/logout.
- GET /api/auth/sessions -> {sessions:[{id,createdAt,expiresAt,current,mfaMethod}]}; DELETE /api/auth/sessions/:id.
- POST /api/auth/totp/setup -> {secret,uri,recoveryCodes}; POST /api/auth/totp/enable {code} -> {ok:true}; POST /api/auth/totp/disable {code} -> {ok:true}. Setup shows authenticator QR/manual key and10 real recovery codes once; codes activate only after TOTP confirmation. POST /api/auth/recovery/verify {code} is a pending-session alternative; POST /api/auth/recovery/regenerate {code:currentTotp} replaces codes. Full recovery-authenticated session may replace TOTP enrollment.
- GET /api/admin/overview -> {stats:{users,allowedEmails,applications,activeApiKeys,mfaEnabled,activeSessions},activity:[audit DTO]}; GET /api/admin/users -> {users:[{id,email,name,avatar,role,totpEnabled,lastLoginAt,createdAt}]}; DELETE /api/admin/users/:id revokes account access, allowlist and sessions with self/last-admin protection.
- GET /api/admin/allowlist -> {emails:[{id,email,role,createdAt}]}; POST /api/admin/allowlist {email,role}; DELETE /api/admin/allowlist/:id (immediate revoke).
- GET /api/admin/applications -> {applications:[{id,name,description,redirectUri,createdAt,revokedAt}]}; POST /api/admin/applications {name,description,redirectUri}; DELETE /api/admin/applications/:id revoke application/tokens/keys.
- GET /api/admin/api-keys -> {apiKeys:[{id,applicationId,name,prefix,scopes,createdAt,expiresAt,lastUsedAt,revokedAt}]}; POST /api/admin/api-keys {applicationId,name,scopes:['identity:read','token:introspect'],expiresInDays:30|60|90|365} -> {key,apiKey:DTO}; DELETE /api/admin/api-keys/:id revoke.
- GET /api/admin/audit -> {events:[{id,actorEmail,sessionId,event,status,target,ip,userAgent,metadata,createdAt}],meta}; pagination plus event/email/status/startDate/endDate filters. Date-only endDate includes full UTC day. Aliases actor_email/start_date/end_date supported with conflict validation.
- GET /api/sso/authorize?response_type=code&client_id=APPLICATION_UUID&redirect_uri=EXACT&state=...&code_challenge=BASE64URL_SHA256&code_challenge_method=S256; requires full session (redirect to /login?returnTo=...). First-party admin-approved apps.
- POST /api/sso/token X-API-Key {grant_type:'authorization_code',code,redirect_uri,code_verifier} -> {access_token,token_type:'Bearer',expires_in:300}; POST /api/sso/introspect X-API-Key {token} -> {active,sub,email,name,exp,aud}.
- GET /api/sso/userinfo Authorization: Bearer ACCESS_TOKEN -> {sub,email,name,email_verified:true}. Access token scope identity:read mandatory. Tokens link to live full MFA session and active allowlisted user/application. Userinfo is uncached. Introspection permits up to5seconds revocation delay by default; set INTROSPECTION_CACHE_SECONDS=0 for per-request validation.

Demo: frontend explicit UI-only demo with labeled banner; no backend bypass. Local fake interactions reset on reload. No default credentials.

## Accepted refinements
- Cookies: opaque random session token only in HttpOnly, Secure on HTTPS, SameSite=Lax, Path=/ cookie with __Host- prefix in production. Never returned in JSON or stored in localStorage. /auth/me returns status=mfa_required|authenticated and method, not the session credential.
- Zod validates request bodies, query and path inputs; SQL parameterization remains mandatory independently of validation. Error statuses:400 malformed input,401 invalid/expired auth,403 MFA/role/CSRF/CORS,404 missing resource,409 conflict,429 rate limit,503 unavailable dependencies/configuration.
- users.deleted_at marks soft deletion; active auth excludes deleted rows. Re-add allowlist is an explicit restoration and audited. Audit actor snapshots retained.
- User/allowlist/application/API-key lists support ?page=1&limit=20&search=; limit max100 and meta {total,totalPages,currentPage,limit}. Audit and MFA-reset queues use keyset cursors as specified below.
- Query-aligned unique/secondary indexes in SQL. OTP lookup uses session_id+expiry rather than searching secret hashes.
- mfa_recovery_codes(id,user_id,code_hash,used_at,created_at); enrollment recovery_hashes JSON. Setup generates cryptographically random codes, hashes in pending enrollment, raw shown once; activate only after TOTP confirmation. POST /auth/recovery/verify {code} is pending-session alternative. POST /auth/recovery/regenerate {code:currentTotp} replaces unused codes. Successful recovery login may replace TOTP enrollment. No silent factor downgrade.
- In-process IP guard before SQL plus configurable shared Redis limiter; MariaDB remains durable shared fallback when Redis is not configured. Redis failure fails closed. Edge/WAF limiting needed for volumetric attacks.
- /sso/userinfo has exact registered origin CORS, bound to access token application for actual requests; no credentialed wildcard CORS. Token/introspection stay server-to-server.

## Security and operational refinements (current implementation)

These definitions extend the base schema/DTO outline above. [001_initial.sql](../server/migrations/001_initial.sql) is canonical indexed DDL and `.env.example` is the configuration reference.

- Production requires configured Google/Gmail/DB secrets and an HTTPS origin. Public database endpoints require verified TLS. Explicit `DB_TLS=false` is supported for localhost, loopback IPs, RFC1918 IPv4 and ULA IPv6 on an operator-verified internal network; a private address alone does not establish isolation or encryption. Arbitrary DNS names and public IPs do not qualify for this exception. No production database changes or bootstrap occur automatically. Personal Gmail uses offline OAuth refresh token; Workspace service-account mode requires domain-wide delegation. Same-mailbox Email OTP is repeated email verification, not an independent factor equivalent to TOTP.
- Optional first-install `/install` is disabled by default. POST `/api/install/check` and `/run` require exact Origin, JSON, a 32-byte random base64url bearer INSTALL_TOKEN, and local throttling; `/run` additionally requires `{confirm:true}`. Server-owned BOOTSTRAP_ADMIN_EMAIL is never accepted from the browser. Installation mode pauses authentication/service APIs and the audit worker. Migrations and bootstrap share one database advisory lock with CLI; bootstrap, its audit event, and the durable installation marker commit atomically. Existing accounts/access/services/audit data or the marker block reinstall. DDL itself is restartable, not rollback-atomic. Disable the flag, clear the token and restart after setup. See [operator guide](INSTALL.md).
- Google code flow binds single-use state to browser cookie, requires PKCE S256, nonce, signature/issuer/audience/expiry/verified-email checks and allowlist. Stable identity is Google sub. Pending session expires10min; successful MFA rotates credential/CSRF, sets absolute default8h expiry and retains at most3 full devices. No sliding renewal.
- `hashToken` uses keyed HMAC-SHA-256 for indexed high-entropy credentials; opaque session/API/access/code secrets use CSPRNG randomBytes(32) or longer and base64url. OTP uses salted Argon2id(19MiB,t=2,p=1) over session-bound HMAC input. PKCE uses standard unkeyed SHA-256. TOTP/enrollment secrets use AES-256-GCM. Email remains searchable plaintext; blind-index field encryption is not implemented.
- OTP default5min/single-use/≤5 attempts. TOTP6digits/30s/±1step rejects reused steps. users.mfa_failed_attempts/mfa_locked_until lock MFA after5 failures for15min across sessions; trusted sessions may still logout/revoke devices. MFA changes revoke other sessions. Recovery codes are random120-bit values, single-use; regeneration and durable audit commit together.
- `/auth/me` adds status(mfa_required|authenticated), mfaMethod(email|totp|recovery|null) and recoveryCodesRemaining for full sessions. Callback success redirects with status=mfa_required and validated returnTo; frontend reads `/me`, never a session credential in JSON.
- Introspection LRU holds at most10,000 entries, keyed by BOTH API-key hash and token hash, with concurrent load coalescing. TTL≤5s and≤earliest token/session/authenticating-key expiry; exp in response is this effective expiry. Inactive/errors are not cached. Additional BFF caching compounds revocation delay and is not enabled by the guide. Use NTP; never extend expired credentials with grace. API-key revocation stops use of that key but does not independently revoke already issued bearer tokens.
- Pool default20/instance, queue100, idle timeout60s, configurable DB_CONNECTION_LIMIT/DB_QUEUE_LIMIT. TLS verifies CA and server identity; DB_CA_FILE is optional (empty uses Node.js trusted CAs); timezone '+00:00' and SET time_zone='+00:00' per connection. Budget connections across all instances/workers/admin reserves and load test. Redis is recommended for high traffic to avoid SQL rate-counter work. Configured Redis failures fail closed rather than resetting counters through fallback.
- Audit schema: audit_logs(id,actor_id,actor_email,session_id,event,status,target,ip,user_agent,metadata,created_at), composite PK(id,created_at), no FK to disposable user/session rows. audit_outbox(id,payload,created_at) stores durable payload; undefined metadata normalizes to {}. Capture success/failure and sanitized reason; never log OTP/key/token/code/verifier/cookie or raw request bodies.
- Security mutations enqueue audit in the mutation transaction where implemented. Request waits for durable enqueue; tracked worker uses FOR UPDATE SKIP LOCKED, INSERT audit_logs and DELETE audit_outbox in one transaction. Three consecutive failed batches stop/fault the worker with sanitized critical output; no silent dropping, auto-quarantine or INSERT IGNORE. Shutdown waits for active requests/worker before closing pool.
- `/api/health` is liveness/setup status. `/api/ready` checks configuration, DB, configured Redis, running/healthy audit worker and oldest pending event<60s. Monitor readiness/backlog and configure on-call alerting externally. Runtime audit grants are SELECT/INSERT only; quarantine/partition/rebuild require separate DBA privileges.
- Archive uses read-only consistent snapshot, keyset(created_at,id) batches1000, JSONL plus checksum manifest and verification. Optional DBA monthly partition uses RANGE COLUMNS(created_at), not MONTH alone. No automatic audit DELETE/DROP PARTITION. Assess outbox fragmentation before maintenance rebuild; retain original evidence for manual quarantine. See [audit runbook](AUDIT-OPERATIONS.md).
- `db:cleanup` removes bounded batches of expired transient sessions/tokens/flows/rate counters only. Log chaining, session IP/UA binding, admin network allowlist and external immutable storage are phase-two/deployment choices.
- SSO is a first-party admin-approved API, not complete/certified OIDC. No discovery, ID tokens, refresh tokens or dynamic registration. [Integration guide](SSO-INTEGRATION.md) describes BFF and reauthorization when access tokens expire.


## User profile and Service RBAC

- Migration `002_service_roles.sql` adds first/last names and per-application memberships, departments and custom roles. See [Service access contract](SERVICE-ACCESS.md) for endpoints, fields, limits and rollout.
- Platform admin/user privileges are separate from service roles. Mutations are admin-only, CSRF-protected and transactionally audited. Composite foreign keys and application-scoped queries reject cross-service assignments.
- All SSO credential stages require an active membership with at least one active assigned role. Existing users receive no automatic grant. Changing a membership revokes its tokens and unconsumed codes; introspection retains its documented maximum 5-second cache delay.
- Introspection and userinfo include only the target application's `roles` and `department`, plus central `given_name`/`family_name`. The consuming backend maps codes to business operations and enforces authorization.
- Public `GET /api/sso/login-context` validates the same callback/PKCE/state as authorize and returns registered branding only. `/login` handles Google, MFA, existing sessions and access-denied states with no browser-readable session credential.


## Security / recovery revision — 2026-09-30

- Migration 004 adds request_id, peer_ip, ip_source, actor_type, application_id, api_key_id to audit_logs, users.otp_sent_at, otp_challenges.reference and sessions.login_application_id. TRUST_PROXY accepts false, loopback, explicit IP/CIDR or legacy one-hop. Trust must match verified reverse-proxy topology. Old audit rows are never rewritten.
- Email OTP sends return {reference,expiresAt,retryAfter}; /auth/me restores that state after reload. Six-digit code must be submitted with its eight-character reference. Database user lock enforces 60-second cooldown across sessions/instances; additional 3/10-minute account/IP quota remains. Delivery failure invalidates the challenge but retains cooldown. Purpose uses only registered Service context; sender display name is CUSA SSO.
- Admin APIs require full TOTP authentication. Email/recovery admin sessions can enroll their Authenticator but cannot administer. Writes require authentication within five minutes, revalidated in the mutation transaction. POST /api/auth/reauth {code} accepts a fresh non-replayed TOTP without extending absolute session expiry.
- Audit list defaults to a seven-day UTC window, permits at most 31 days, and uses descending (created_at,id) with cursor; return meta {limit,hasMore,nextCursor,startAt,endBefore}. Preserve filters and server-returned time bounds between pages; page=1 is accepted for compatibility, deeper OFFSET pages are rejected. Access searches are audited.
- Browser and machine coarse quotas are separate. Authenticated /token+/introspect quotas are shared 3000/min/application and 1500/min/key; API-key authentication occurs before introspection cache access. Introspection identity query is one SELECT without transaction locks or per-call last_used_at writes. This does not mean every HTTP request performs only one SQL operation (credential/quota checks still apply).
- Production API fails closed for stopped/faulted audit worker, queue >=10000, oldest >=300 seconds or unreadable queue. Probe cache is at most five seconds. /health and /ready remain available; readiness is stricter (oldest <60 seconds). External alerts and effective database grants must be configured independently.
- Migration 005 adds mfa_reset_requests and mfa_reset_reviews. Owner submits evidence from Google-authenticated MFA screen; no caller-selected user ID. Encrypted, watermarked JPEG/PNG evidence is outside public roots. MFA_EVIDENCE_KEY is a separate 32-byte master key wrapping per-document keys; original plaintext is never persisted.
- Reset requests bind the current encrypted factor digest. Admin cannot self-review; fresh TOTP and recent evidence viewing are required; admin targets need two other distinct admins. Approval clears factor/recovery codes/all sessions and associated tokens atomically with audit. A changed factor or unavailable evidence blocks approval.
- Evidence lifetime: 7 days from approval/rejection; pending max30 days; durable upload intents allow cleanup after crashes. Scheduled purge plus in-process job destroys key then ciphertext and records purged_at/audit. Seven days is organizational policy, not a blanket statutory requirement. Exclude files and wrapped keys from backups/snapshots; see [MFA reset operating contract](MFA-RESET.md).
- MFA reset list is keyset-paginated at 50 rows; metadata nextCursor/hasMore. Evidence never appears in JSON/audit logs, public URLs, static assets or service claims. Public privacy notice v1.1 describes purpose, minimization, recipients and retention.
- [OpenAPI 3.1](../web/public/openapi.json) documents the SSO integration endpoints only. Admin/auth/MFA endpoints are documented in this contract and MFA runbook; no claim that the OpenAPI file covers the full administrative API.
